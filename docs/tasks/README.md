# How an agent picks a task

Read `AGENTS.md`, `docs/PLAN.md`, `docs/REVIEW.md`, and `docs/WORKFLOW.md` first. Then open `docs/BOARD.md`.

"Let's go" means `docs/WORKFLOW.md`. Do only the Done when list. Do not invent facts or credentials.

## Pick

Take the lowest-numbered task whose Status is Ready, whose Depends are all Done, and whose Owns paths do not overlap a task that is In progress.

`023` sorts before `023a`. Compare the number, then the letter suffix. `003` is lower than `004`. `023a` is lower than `023b`.

One agent, one task file. Start a new session for that task. Do not pick a second task in the same session.

A different session reviews the result, using `docs/REVIEW.md`. The reviewer does not implement the next task.

## What this session may edit

- The task file it picked. Set Status to In progress at the start and Done at the end.
- Paths listed under Owns.
- A new decision file the task requires, plus `docs/decisions/INDEX.md` regenerated by `./scripts/regenerate-decision-index.sh`.
- `docs/BOARD.md`, only by running `./scripts/regenerate-board.sh` after the Status change.
- `docs/work/NNN-....md` for this task's own log. The next number after `002-execution-plan.md`. An agent does not edit another task's work file.

## What this session does not edit

- Paths under Does not touch.
- Another task file.
- CalorieCounter. It is read only.
- `catalog/catalog.db`, unless this task is 007 and the size check allows a normal git blob.
- A `.sq` file or a SQLDelight migration owned by another task.

## Status

- Ready. Every dependency is Done, and Owns does not overlap an In progress task.
- In progress. A session is doing the task.
- Blocked. A dependency is not Done.
- Done. The Done when list is true and review passed.

When a task becomes Done, the session that finished it checks tasks that list it in Depends. If every dependency of such a task is Done, and Owns does not overlap an In progress task, that session sets it to Ready and regenerates the board. It does not start the newly Ready task.

## Lanes

Lane S is a `:sharedLogic` package whose Owns do not overlap another In progress task.

Lane C is the migration and catalog writer. Two Lane C tasks are never both Ready. The Depends lines are the queue.

Lane A is `androidApp` UI after the shared contract is Done. One Lane A task is Ready at a time, because they share the nav host. Lane I is the same for `iosApp`.

Lane A and Lane I for the same feature can both be Ready. They do not share paths.

## Before code that changes behavior

Write the failing test and commit it. Then implement. Do not squash those commits.

Before code that changes schema, modules, a shared API, a bundled file, or test strategy, write the decision file. Then implement. Do not wait for a person.

## Done

Run the command in the task. Open the pull request. A different session reviews it. Set Status to Done only after that review and after the GitHub checks are green, or after the local command is green when task 005 is not on `master` yet. Regenerate the board. Distribute only as `docs/WORKFLOW.md` says. Do not start the next task.
